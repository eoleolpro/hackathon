# WILLCHAIR RESCUE

휠체어 사용자가 위치를 확인하고 필요한 연락 대상에게 직접 공유하는 구명조끼 연동형 프론트엔드 프로토타입입니다.
이번 버전은 **1단계 위치 수신, 2단계 지도·공유, 3단계 보관함 이벤트 시뮬레이션**을 구현합니다.
실제 BLE, 자동 문자 발송, 구조기관 연계, 상대방 수신 확인은 구현하지 않았습니다.
실제 안전 장비로 사용할 수 있는 제품이라는 주장을 하지 않습니다.

기존 WILLCHAIR FLOOD는 `/?mode=flood`에서 유지합니다. 메인 화면 하단의 접이식 보조 도구 링크로 새 탭에서 열 수 있습니다.
기존 기능 설명과 한계는 [FLOOD_README.md](FLOOD_README.md), 기존 품질 보고서는 [QUALITY_REPORT.md](QUALITY_REPORT.md)에 보존합니다.

## 기존 구조 분석과 재사용

기존 프로젝트는 React + Vite + TypeScript, Leaflet + React-Leaflet, Turf.js 기반이며 다음을 갖추고 있었습니다.

- 타일 로딩·실패·재시도 훅과 지도 오류 경계
- 지도 이벤트·마커·침수·경로 레이어 분리
- 경로/등시간선 제공자 인터페이스, 시뮬레이션 분석, Playwright·axe 점검
- 네이비·청록색 디자인 토큰 및 반응형 CSS

기존 App 화면은 `src/FloodDashboard.tsx`에 보존했습니다. 해당 화면의 지도·경로·타임라인·대피 후보 기능을 삭제하지 않았습니다.
RESCUE는 기존 `useMapTiles`, `MapLoadingStatus`, `MapErrorBoundary`, Leaflet CSS, 디자인 토큰과 개발 도구를 재사용합니다.
새 위치·공유·장치 계층은 FLOOD의 임의 좌표/가상 데이터와 연결하지 않습니다. 새 런타임 라이브러리는 설치하지 않았습니다.

## 설치·실행

Node.js 요구사항: `^20.19.0 || >=22.12.0`. 이번 환경은 Windows, Node.js 26.13.0, Chrome입니다.

```sh
npm ci
npm run dev
npm run build
npm run preview
npm run lint
```

개발 서버가 출력하는 Local 주소를 엽니다. 기본은 `http://localhost:5173/`이며 사용 중이면 다음 포트를 선택합니다.
자체 서버·DB·로그인·API 키 설정은 없습니다. 지도 타일에는 인터넷 연결이 필요합니다.

**위치 수신은 HTTPS 보안 컨텍스트가 필요**합니다. 개발 컴퓨터의 localhost는 예외적으로 허용됩니다.
휴대전화에서 컴퓨터의 `http://192.168...` 주소로 접속하면 일반적으로 위치 수신이 제한됩니다. 실제 폰 검증에는 HTTPS 테스트 주소를 사용하세요.
이 작업에서는 외부 배포를 수행하지 않았습니다. 위치 권한·보안 컨텍스트·관찰 중지는 [MDN watchPosition](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/watchPosition)의 조건을 따릅니다.

## 기능과 상태

### 긴급 위치 모드

- 앱 로드나 보관함 시뮬레이션만으로 위치 권한을 요청하지 않습니다.
- 사용자가 **긴급 위치 모드 시작** 또는 분리 제안의 **위치 모드 활성화**를 선택하면 `watchPosition()`을 호출합니다.
- 사용자 권한 허용 후 위도·경도·정확도·측정 시각을 수신하며 새 위치마다 갱신합니다.
- 위치 수신 전/수신 중/확인됨/확인 실패/종료를 구분합니다. GPS 연결 완료라고 표현하지 않습니다.
- 정확도 100m 초과, 측정 후 60초 이상 경과 시 주의를 표시합니다. 이는 앱의 표시 기준이며 안전 판단 기준이 아닙니다.
- 권한 거부, 미지원, 시간 초과, 측정 실패, 유효하지 않은 좌표, HTTPS 미충족을 구분합니다.
- **긴급 모드 종료**는 항상 활성 상단 바에서 이용할 수 있습니다. `clearWatch()`와 콜백 세대 검증으로 관찰과 늦은 결과를 정리합니다.
- 컴포넌트 해제에도 관찰을 중지합니다. 모드 종료 시 위치·공유 화면을 비우고 지도는 초기 강남역 화면으로 돌립니다.
- 백그라운드·화면 잠금·배터리 절약 상태에서 지속 추적을 보장하지 않습니다.

### 지도

- 마지막 수신 좌표에 내 위치 마커, `coords.accuracy`(m)에 해당하는 원을 표시합니다.
- 첫 위치는 지도를 이동시키고, 이후 좌표는 마커/원을 갱신합니다. 사용자가 지도를 이동한 경우 **현재 위치로 이동**으로 다시 중심을 맞출 수 있습니다.
- 위치가 없을 때 초기 강남역 지도를 사용자 위치로 표현하지 않습니다.
- 정확도 수치나 원은 실제 오차를 완전히 보장하지 않습니다.
- OpenStreetMap 출처·타일 로딩/실패·재시도를 표시합니다. 타일 수신 시각과 위치 측정 시각을 구분합니다.
- 지도 표시 지역의 타일 요청이 OpenStreetMap에 전달될 수 있음을 시작 전 안내합니다.

### 위치 공유와 전화

- 위치가 없으면 공유 버튼은 비활성화됩니다.
- 사용자가 **현재 위치 공유**를 눌렀을 때 좌표의 복사본으로 메시지를 생성합니다.
- 서비스명, 긴급 위치 공유 요청, 위도·경도, 측정 시각(KST), 정확도, OpenStreetMap 링크를 포함합니다.
- 오래됨/낮은 정확도는 메시지에도 포함합니다. 이후 위치 갱신이 기존 공유 메시지를 바꾸지 않습니다.
- 사용자 클릭 안에서 `navigator.share()`를 우선 호출합니다. 미지원/실패 시 미리보기와 **공유 메시지 복사**를 제공합니다.
- Clipboard API도 보안 컨텍스트와 브라우저 정책의 영향을 받습니다([MDN writeText](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText)). 자동 복사도 실패하면 읽기 전용 메시지를 사용자가 직접 선택해 복사할 수 있습니다.
- 공유 화면 요청/시스템 절차 반환/취소/오류/복사를 구분합니다. 시스템 공유 절차 반환을 전송 완료로 해석하지 않습니다.
- Web Share의 반환 시점은 플랫폼마다 다르므로 수신 확인으로 해석하지 않습니다([MDN Navigator.share](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)). 상대방 수신 상태는 별도로 **미확인**입니다. 이번 버전에는 수신 확인 통신이 없습니다.
- 공유는 좌표 스냅샷이며 실시간 추적 링크가 아닙니다. 연락 대상은 사용자가 기기 공유 화면에서 직접 선택합니다.
- `tel:119`는 전화 앱을 엽니다. 실제 전화·신고 접수·구조 요청 완료를 앱에서 확인하지 않습니다.
- 119 링크를 React 밖의 정적 HTML에 배치해 앱 오류·JavaScript 비활성 상태에서도 안내를 확인할 수 있습니다.

### 구명조끼 보관함 시뮬레이션

- `STORED`: 보관함 수납, `REMOVED`: 보관함 분리, `DISCONNECTED`: 센서 연결 끊김, `UNKNOWN`: 상태 확인 불가.
- 기본 상태는 UNKNOWN이며 실제 센서는 미연결입니다.
- 보관함 분리 버튼은 MockDeviceAdapter 이벤트를 발생시키고 활성화를 제안합니다. 자동 추적/자동 공유를 시작하지 않습니다.
- 연결 실패·연결 끊김·상태 미확인도 테스트 버튼으로 전환할 수 있습니다. 모두 시뮬레이션으로 표시합니다.
- 탈착 상태로 착용 여부를 판단하지 않습니다. 실제 착용 여부는 항상 미확인입니다.
- 모드 종료 시 활성화 제안과 위치/공유 세션만 정리하며, 보관함 상태를 수납으로 바꾸지 않습니다.

## 저장·개인정보 정책

- 좌표·공유 메시지·연락처를 localStorage, 서버, DB, 분석 서비스, 콘솔에 기록하지 않습니다.
- 현재 버전은 민감하지 않은 사용자 설정도 영구 저장하지 않습니다.
- 위치 권한은 사용자 선택 때만 요청합니다. 공유/복사/지도 외부 링크/전화는 별도 사용자 동작입니다.
- 위치 모드 종료 시 앱의 현재 위치·공유 메시지 상태를 제거합니다. 이미 공유한 메시지, 브라우저 타일 캐시, 운영체제 클립보드는 앱에서 회수할 수 없습니다.
- 외부 지도 타일 요청에는 표시 지역 정보가 포함될 수 있습니다. 이 점은 시작 전과 설정 화면에서 안내합니다.

## 폴더와 후속 인터페이스

```text
src/
  App.tsx                          RESCUE 기본 / FLOOD 보조 화면 분기
  FloodDashboard.tsx               기존 FLOOD 화면 보존
  components/
    emergency/                    위치·공유·설정·RESCUE 레이아웃
    device/                       보관함 상태와 시뮬레이션 제어
    common/                       119 안내·RESCUE 오류 경계
    map/                          기존 지도 레이어 + 내 위치·정확도 원
  hooks/
    useEmergencyLocation.ts       위치 관찰 수명·상태·오류·오래됨
    useLocationShare.ts            공유 스냅샷·진행 상태·수신 미확인
    useDeviceEvents.ts             어댑터 이벤트 구독
  services/
    locationService.ts            Geolocation API 경계
    shareService.ts               메시지·Web Share·Clipboard
  adapters/
    deviceAdapter.ts              DeviceEventAdapter 계약
    mockDeviceAdapter.ts          시뮬레이션 이벤트만 제공
  types/
    location.ts                   위치·공유·후속 수신 확인 타입
    device.ts                     DeviceEvent·DeviceConnectionStatus
  utils/                          위치 품질/시간·장치 표시 및 기존 분석
```

4단계 BLE: `DeviceEventAdapter.getSnapshot/subscribe/disconnect` 계약을 구현하는 BLEDeviceAdapter를 추가합니다.
현재 MockDeviceAdapter만 존재하며 장치 검색/페어링/연결 성공을 구현하지 않습니다. 향후 어댑터 교체는 위치 훅과 지도에 영향을 주지 않도록 분리했습니다.
5단계 수신 확인: `LocationShareProvider`, `RecipientReceiptAdapter`, `RecipientReceiptEvent` 계약만 정의했습니다.
실제 연락 대상 전송 채널·인증·동의·수신 확인 프로토콜이 정해지기 전에는 수신 완료 상태를 만들지 않습니다.

## 자동 검증

```sh
npm run test:e2e -- e2e/rescue.spec.ts
npm run test:e2e -- e2e/quality.spec.ts
npm run test:e2e
```

설치된 Chrome을 기본 사용합니다. 필요하면 `npx playwright install chromium` 후 `PLAYWRIGHT_CHANNEL=chromium`을 지정합니다.
테스트는 브라우저의 가상 좌표 또는 테스트 전용 콜백을 사용합니다. 실제 개인 좌표 수신, OS 공유 대상 전송, 실제 통화를 검증한 것이 아닙니다.
리포트는 `playwright-report/`, 실패 trace·스크린샷은 `test-results/`이며 Git에서 제외됩니다.
상세 결과와 미검증 항목은 `RESCUE_PHASE1_REPORT.md`에 기록합니다.

## 실제 스마트폰 검증 절차 — 별도 수행 필요

1. HTTPS 테스트 주소를 휴대전화 Chrome/Safari에서 엽니다. 초기에는 권한 팝업/위치 마커가 없어야 합니다.
2. 긴급 위치 모드 시작을 누릅니다. 실제 권한 팝업에서 거부 시 안내가 나오고, 허용 시 현재 좌표·정확도·측정 시각이 표시되는지 확인합니다.
3. 안전한 장소에서 위치가 변하면 좌표와 마커·정확도 원이 갱신되는지 확인하고, 지도를 다른 곳으로 옮긴 뒤 현재 위치로 이동을 누릅니다.
4. 통신 불량·실내·시간 경과에 따른 낮은 정확도/오래된 위치 안내를 확인합니다. 실제 위험 상황에서 시험하지 않습니다.
5. 공유 버튼을 눌러 OS 공유 화면을 확인한 후 취소합니다. 필요하면 동의한 테스트 연락 대상에게만 메시지를 보내고 측정 시각·정확도·OSM 링크를 확인합니다. 앱은 상대방 수신 미확인을 유지해야 합니다.
6. 공유 미지원 브라우저에서 복사 버튼과 수동 선택을 확인합니다. 외부 클립보드 내용은 테스트 후 사용자가 직접 정리합니다.
7. 모드를 종료한 뒤 위치 마커/메시지가 사라지고 권한 사용 표시/위치 관찰이 중지되는지 확인합니다. 다시 시작해도 이전 공유 내용은 복원되지 않아야 합니다.
8. 보관함 분리 시뮬레이션으로 제안만 표시되고, 활성화를 선택해야 권한 요청이 발생하는지 확인합니다. 착용 미확인·실제 센서 미연결 안내를 확인합니다.
9. 잠금/백그라운드 후 돌아와 시각·오래됨 표시를 확인합니다. 지속 추적을 보장하는 시험으로 해석하지 않습니다.
10. 119 버튼은 링크와 전화 앱 연결까지만 확인합니다. 시험 목적으로 실제 긴급 전화를 걸지 않습니다.
11. VoiceOver/TalkBack·키보드·글자 확대에서 시작/종료/공유/전화 안내의 탐색과 읽기를 확인합니다.

실제 스마트폰, 실제 센서, OS 공유 완료와 수신, 화면 잠금 지속 추적, 긴급 전화 통화는 이번 개발 환경에서 검증할 수 없습니다.
