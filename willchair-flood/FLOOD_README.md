# WILLCHAIR FLOOD

휠체어 사용자가 가상 침수 상황에서 이동 조건·경로·대피 후보를 비교하는 프론트엔드 시나리오 서비스입니다.
React + Vite + TypeScript, Leaflet + React-Leaflet, Turf.js, Lucide React, 일반 CSS를 사용합니다.
기존 지도·시나리오·경로·타임라인·가상 시간 범위·후보 비교 기능을 유지합니다.

## 설치 및 실행

Vite의 Node.js 요구사항은 `^20.19.0 || >=22.12.0`입니다. 이번 점검 환경은 Windows, Node.js 26.13.0, Chrome입니다.

```sh
npm ci
npm run dev
```

서버가 출력하는 주소를 엽니다. 기본 주소는 `http://localhost:5173/`이며 이미 사용 중이면 개발 서버가 다른 포트를 선택할 수 있습니다.
백엔드·DB·로그인·API 키·환경변수 설정은 필요하지 않습니다. OpenStreetMap 타일에는 인터넷 연결이 필요합니다.

```sh
npm run build       # 로컬 자료 수정 시각 메타데이터 갱신 + TypeScript 엄격 검사 + dist 빌드
npm run preview     # 빌드 결과 확인
npm run lint        # Oxlint 검사
npm run test:e2e    # Chrome으로 기능·접근성·반응형·실패 복구 검증
```

브라우저 테스트에는 설치된 Google Chrome이 기본으로 사용됩니다. 다른 Playwright Chromium을 사용하려면 다음을 실행합니다.

```sh
npx playwright install chromium
```

실행 시 `PLAYWRIGHT_CHANNEL=chromium`을 환경변수로 설정합니다. PowerShell에서는 `$env:PLAYWRIGHT_CHANNEL='chromium'`입니다.
테스트는 localhost:5173 개발 서버를 재사용하거나 시작합니다. 충돌하는 다른 프로젝트 서버는 먼저 종료하세요.
리포트는 `playwright-report/index.html`, 실패 trace와 확인용 스크린샷은 `test-results/`에 생성됩니다. 두 폴더는 Git에서 제외합니다.

## 기능 확인 순서

1. 지도 클릭으로 출발→도착을 지정합니다. 이후 클릭은 두 지점을 번갈아 변경합니다.
2. **시연 출발·도착지 선택**을 누르면 준비된 일반·우회 후보 경로를 표시합니다. 경로 선이나 패널 버튼을 선택해 거리·중첩·접근성 상태를 비교합니다.
3. 임의 두 점을 고르면 준비된 경로가 없을 때 **경로 계산 불가**를 표시합니다. 임의 연결선을 생성하지 않습니다.
4. 집중호우를 선택하고 0·15·30·45·60분을 변경하면 지도 Polygon과 경로·지점·후보의 중첩을 다시 분석합니다.
5. **가상 범위 기준 출발지 선택** 후 5·10·15분 가상 범위를 비교합니다. 범위 안 후보가 각각 1·2·3곳입니다. 다른 출발지는 준비된 등시간선 없음을 안내합니다.
6. S 마커 또는 후보 카드로 출입구·접근성·운영 상태를 확인합니다. 비어 있는 정보는 **미확인**, 임의 속성은 **가상 설정**입니다.
7. **시뮬레이션 전체 초기화**는 시간 0분·평상시·가상 범위 5분·출발지 지정 대상·영역 표시 켜짐·강남역 기본 지도로 복원하고 좌표·경로/후보 선택을 제거합니다.

## 키보드 조작

- 첫 Tab으로 **본문으로 바로가기**에 접근할 수 있습니다.
- Tab으로 지도에 진입한 후 방향키로 이동, `+`/`-`로 줌, Enter로 중심 좌표를 출발지 또는 목적지로 지정합니다.
- 경로·침수 Polygon은 Tab 후 Enter/Space로 선택합니다. 침수 구역 선택은 중심 좌표 지정과 설명 팝업을 함께 수행합니다.
- 대피 후보 마커는 Enter/Space로 팝업과 후보 선택을 함께 갱신합니다.
- 시나리오 라디오와 시간 슬라이더는 방향키를 지원합니다. 접이식 패널은 summary에 포커스 후 Enter로 열고 닫습니다.
- 위험 상태는 색상 외에 텍스트, 경로 종류는 실선/점선, 마커는 출발/도착/S 텍스트로 구분합니다.

## 실제 지도와 시뮬레이션 구분

| 자료 | 출처 및 의미 | 갱신 시각 |
| --- | --- | --- |
| 배경 지도 | OpenStreetMap contributors의 외부 지도 타일 | 원본 갱신 미확인. 마지막 타일 수신 시각만 별도 표시 |
| 침수 Polygon | 직접 작성한 가상 GeoJSON | 로컬 파일 수정 시각. 관측·예측 시각 아님 |
| 경로 | 사전 준비된 시연 LineString 2개 | 로컬 파일 수정 시각 |
| 등시간선 | 고정 출발지 기준의 가상 시간 범위 | 로컬 파일 수정 시각. 실제 시간 계산 아님 |
| 대피 후보·속성 | 가상 시설 3곳 및 가상/미확인 정보 | 로컬 파일 수정 시각. 실제 시설 확인 아님 |

화면 하단 **데이터 출처 및 갱신 정보**에서 링크와 KST 시각을 확인합니다.
`npm run build` 또는 `npm run data:metadata`가 `public/data/metadata.json`을 파일 mtime에서 생성합니다.
클론·복사·배포 환경의 파일 수정 시각이므로 자료의 실제 관측 갱신 이력으로 해석하지 않습니다.
침수 그룹은 5개 파일 중 마지막 수정 시각입니다. 출처 파일을 읽지 못하면 갱신 시각 미확인으로 표시합니다.

## 공간 분석과 한계

- GeoJSON은 `[lng, lat]`, Leaflet 위치 배열은 `[lat, lng]`, 상태는 `{lat,lng}`입니다.
- Turf.js `length`로 좌표 길이를 계산합니다. 일반 경로 약 353m, 우회 후보 약 709m입니다.
- 준비된 경로 끝점과 일치할 때만 표시합니다(부동소수점 오차 1e-8도 미만만 허용). 역방향 선택은 좌표 순서를 뒤집습니다.
- `booleanPointInPolygon`은 지점·후보의 포함을, `booleanIntersects`는 경로와 침수 Polygon의 중첩을 분석합니다. 경계 접촉도 포함합니다.
- **가상 중첩 없음은 실제 안전·도달·접근성을 뜻하지 않습니다.** 실제 위험도 계산·휠체어 이동 가능 판정을 하지 않습니다.
- 0·15·30·45·60분은 직접 준비한 Polygon이며 지형·강우·배수 모델 또는 buffer 연산 기반 예측이 아닙니다. 안내문은 접을 수 없는 고정 영역에 표시합니다.
- 평상시에는 모든 시점의 활성 침수 영역이 0개입니다. 집중호우는 서측 1개, 침수 발생은 3개입니다.
- 집중호우 0분: 두 경로 중첩 없음. 15/30분: 일반만 중첩. 45/60분: 두 경로 모두 중첩되어 우회 후보 결과 없음.
- 등시간선은 시연 출발지 `{lat:37.498,lng:127.0255}`에서만 제공하는 가상 시간 범위입니다. 임의 출발지로 이동시키거나 실제 이동시간을 계산하지 않습니다.
- 도로·보도 연결, 턱·경사도, 실시간 침수, 시설 운영·출입구·수용인원은 실제 검증하지 않았습니다.
- 별도 서버·영구 저장소가 없으며 새로고침하면 입력 상태가 초기화됩니다.

## 로딩과 실패 처리

- 타일 로딩, 일부 타일 실패, 15초 응답 대기 시간 초과를 구분하고 **지도 타일 다시 시도**를 제공합니다. 성공한 타일이 이전 실패를 덮어쓰지 않습니다.
- 지도 렌더 오류는 오류 경계에서 격리하며 재시도할 수 있습니다. 좌표·정보 패널은 유지합니다.
- 정적 데이터는 실제 파일을 fetch합니다. HTTP·네트워크·JSON 오류에 자료 이름을 붙여 안내합니다.
- 시간별 자료 5개 중 하나라도 실패하면 침수 분석은 미확인으로 처리하며 후보를 안전하다고 제시하지 않습니다.
- 좌표 변경 시 이전 경로·등시간선 결과를 숨기고 이전 요청을 취소합니다.
- 영역 숨김은 분석 중지가 아닙니다. 선택 시나리오·시간에 대한 분석은 유지합니다.

## 코드 구조

```text
src/
  App.tsx                     화면 조합
  hooks/useDashboard.ts       선택 상태, 초기화, 파생 분석
  hooks/useMapTiles.ts        타일 로딩·실패·재시도
  hooks/useFloodData.ts        시간별 자료 로딩
  hooks/useRouting.ts         경로 제공자 연결 및 요청 수명 관리
  hooks/useIsochrones.ts       등시간선·후보 로딩
  components/                 입력·정보·타임라인·후보·출처 UI
  components/map/             지도 이벤트, 접근 가능한 레이어, 마커, 오류 경계
  routing/                    RoutingProvider 및 시연 구현체
  isochrones/                 IsochroneProvider 및 시연 구현체
  data/                       예시 기준점·시나리오·시간 상수
  utils/                      공간 분석·좌표 변환·GeoJSON/출처 검증·파일 요청
public/data/                  정적 시뮬레이션 GeoJSON 및 출처 메타데이터
scripts/update-data-metadata.mjs
playwright.config.ts
e2e/quality.spec.ts
```

`RoutingProvider.getRoutes({origin,destination,signal})`와
`IsochroneProvider.getIsochrones({origin,ranges,signal})`는 후속 OpenRouteService 연결을 위한 인터페이스입니다.
현재 구현체는 정적 파일만 사용합니다. 실제 API 제공자는 반환 형식을 정규화해 훅에 주입해야 합니다.
침수 검증기는 구멍 없는 단순 Polygon, 시연 등시간선 검증기는 준비된 직사각형만 지원하므로 실제 API 데이터 검증은 별도로 설계해야 합니다.

## 검증 범위

최신 결과와 수동 확인 체크리스트는 `QUALITY_REPORT.md`를 참고하세요.
브라우저 사용자 흐름은 Playwright를 통해 클릭·키보드·터치 에뮬레이션으로 재현하고, 데스크톱/모바일 스크린샷을 별도로 확인합니다.
자동 접근성 검사는 스크린리더 실사용이나 접근성 인증을 대체하지 않습니다.
실제 휴대전화·핀치 제스처·Safari/Firefox·스크린리더·실제 휠체어 이동 검증은 별도로 필요합니다.
과거 단계별 구현 기록은 `PHASE3_REPORT.md`부터 `PHASE7_REPORT.md`에 보존합니다.
